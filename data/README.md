# Dataset layout

`projects/` holds one markdown file per project and is the single place a project is described. Each file's frontmatter carries three blocks with different owners, and the boundary is load-bearing:

- `curated` — written and reviewed by a person. The authority for identity, host, status, category, capabilities, registry names, and licensing decisions. **No script writes this block.**
- `collected` — regenerated by `a080_build_project_files.py` from the newest snapshot. Stars, commits, downloads, size estimate, and `repository_url`. The URL is derived from `curated.repository` and `curated.forge.host` on every rebuild rather than stored by hand, so it cannot drift from them; it is repeated as a link at the top of the body. Hand-edits here are lost on the next rebuild.
- `summary` — provenance for the agent-written prose in the body: models, timing, tokens, API cost.

The plotting code reads `curated` and `collected` directly from these project files.
The CSV snapshot remains the historical, downloadable export used by the catalog and
must have the same date as every `collected.snapshot` value before a plot is built.

The body is the agent summary itself: prose written by an independent agent that read
what the project publishes about itself, generated by `a070_agent_summaries.py`. It exists
because the `capabilities` tags are a controlled vocabulary applied by one reviewer —
comparable across projects, but thin, and carrying that reviewer's reading of each one. A
separate agent describing each project from its own documentation gives the catalog a
second account, one that can disagree.

Read those summaries critically. The agent reports what a project *claims*; where a
repository advertises features it does not ship, the summary describes the advertisement.
Compare it against `curated.status` and `curated.decision_reason`, which record what review
found. The disagreements are the useful part — this is how a private repository and two
source-less repositories were caught sitting in the catalog as reusable software. Agent
claims are not authoritative either: in the first run the agent reported that jDAS
publishes no source, and it publishes seven Python files. Verify before acting on any
single statement.

Token counts, models, timing, and `api_list_cost_usd` in the `summary` block come from the
API response, not from the agent. A model cannot observe its own token usage, so asking it
to report that number would produce an invention. Metrics that no free source publishes are listed under `collected.unavailable` with the reason, rather than being silently omitted.

Two fields are easy to confuse. `status` records a scope judgement — whether a project belongs in the comparison at all. `license_class` records reuse terms (`osi-approved`, `source-available`, `unlicensed`, `unknown`) and never affects `status`, so the open-source share of the ecosystem can be counted from the catalog instead of being built into it. `forge` names the host; it defaults to GitHub, and `repository` is a namespace path, which may have more than two segments on GitLab.

Each `snapshots/YYYY-MM-DD/` directory contains:

- `raw/*.jsonl`: compact source records used to build the public tables.
- `projects.csv`: one row per reviewed project, including watchlist and exclusions.
- `metrics.csv`: tidy numeric observations with units, source URLs, windows, timestamps, and missingness reasons.
- `publications.csv`: canonical and related DOI records without citation roll-up.
- `capabilities.csv`: normalized manually reviewed capability tags.
- `pypi_daily.csv`: mirror-filtered daily PyPI counts where available.
- `dependencies.csv`: direct runtime requirements from PyPI package metadata, with links back to any matching catalogued project. Optional extras are excluded.
- `candidates.csv`: discovery results across every searched host, with current review decisions.
- `discovery_coverage.csv`: one row per discovery probe recording what it retrieved, what the host claimed to hold, whether the result was truncated, and any failure. Absence of candidates from a host means nothing without this file.
- `manifest.json`: schema version, generation time, source notes, and SHA-256 checksums.
